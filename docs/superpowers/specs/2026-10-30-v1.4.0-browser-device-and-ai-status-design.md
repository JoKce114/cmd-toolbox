# v1.4.0：浏览器快捷键与移动端模拟、AI 页签状态

日期：2026-10-30
状态：待实施
前置：`2026-10-29-v1.3.0-editor-appearance-and-startup-design.md`

## 背景

三个问题都来自日常使用，互相独立：

1. **浏览器没有 F5**。刷新只能拿鼠标点工具栏按钮。焦点落进网页后更是连
   应用层的快捷键都收不到，必须先把鼠标移回工具栏。
2. **浏览器没法看移动端布局**。内置浏览器固定按桌面宽度渲染，
   临时想确认一个页面在手机上的样子，只能拖窄窗口——而拖窄窗口改的是
   布局宽度，不是设备视口，媒体查询和 `devicePixelRatio` 都不对。
3. **AI 页签看不出谁在跑**。`src/App.tsx:1264` 的 `modelStatusByGroup`
   只按**项目**汇总一个灯（`src/components/Sidebar.tsx:94`），
   同一个项目里同时开 claude 和 codex 时，侧栏只显示一个合并状态。
   而且任务跑完之后灯直接变回绿色，与「一直空闲」没有区别——
   用户不知道结果是「刚跑完」还是「根本没跑」。

## 需求范围

### 做

- 浏览器页签支持 F5 / Ctrl+R 刷新，Ctrl+Shift+R / Shift+F5 强制刷新；
  焦点在网页内部时同样生效
- 浏览器页签支持移动端模拟：常见机型预设、横竖屏切换、自定义宽高；
  模拟时切换移动端 UA
- AI 终端页签在页签栏上直接显示状态灯（回答中 / 等待确认 / 报错）
- 任务结束且用户没看过的页签显示「已完成未读」标记，切过去即清除
- 未读状态向上汇总到侧栏项目行，跨项目也能看到

### 不做

- 触摸事件模拟（鼠标改触摸）。`enableDeviceEmulation` 不含触摸，
  需要额外挂 `debugger` 发 CDP 命令，本版不做
- 设备像素比 / 网络限速 / CPU 降频等 DevTools 完整面板功能
- 浏览器多窗口、标签分组
- 把 AI 状态同步到系统任务栏或托盘
- 通过屏幕内容（OCR / 视觉）判断任务状态，仍沿用现有输出文本启发式

## 设计

### 一、F5 刷新

焦点有两种情况，必须分别覆盖：

| 焦点位置 | 事件落点 | 处理位置 |
|---|---|---|
| 地址栏、工具栏 | 应用渲染进程 | `BrowserPane` 的 `onKeyDown` |
| 网页内部 | `<webview>` 的 guest 渲染进程 | 主进程 `before-input-event` |

主进程是权威路径。`desktop/pane-api.js:544` 的 `attachBrowser()` 已经把
`tabId → webContentsId` 存进 `guests`，在这里给 guest 挂一次监听：

```js
content.on('before-input-event', (event, input) => {
  if (input.type !== 'keyDown') return;
  const key = String(input.key || '');
  const isReload = key === 'F5' || (input.control && key.toLowerCase() === 'r');
  if (!isReload) return;
  event.preventDefault();
  if (input.shift) content.reloadIgnoringCache();
  else content.reload();
});
```

要点：

- 只处理 `keyDown`，`before-input-event` 对 keyDown / keyUp 都会触发
- 必须 `preventDefault()`，否则页面自己绑的 F5 也会执行
- 只对浏览器 guest 生效，终端页签走的是 `node-pty`，不经过这里
- `attachBrowser` 可能被调用多次（`did-attach` 和应用启动各一次），
  用 `guests` 是否已存在判断，避免重复挂监听

### 二、移动端模拟

**实测结论（2026-10-30，`tests/device-emulation-probe.mjs`）：不要用
`enableDeviceEmulation`。**

它在 `<webview>` 的 guest 上会按可用区域缩放内容：请求 375×667 时，
`screen` 确实是 375×667，但 `innerWidth` 变成 981、`innerHeight` 变成 1744，
视口完全错位，媒体查询结果也是错的。这个 API 面向 `BrowserWindow` /
`BrowserView` 场景，不适合嵌入式 webview。

**采用纯前端方案**：把 `<webview>` 元素本身设成设备尺寸，CSS 视口随之
变成 375×667（探针已验证），媒体查询、`innerWidth`、`innerHeight` 全部正确。
UA 用 webview 元素自带的 `setUserAgent()`（`electron.d.ts:21372`），
同样不需要主进程。**本方案不新增任何 IPC 通道。**

**前端布局**：`<webview>` 外面包一层 `.browser-stage`
（`overflow: auto`、`display: flex`、居中），模拟时给 webview 设
`width` / `height` 为设备尺寸并 `flex: 0 0 auto`，桌面模式恢复 `100%`。
设备宽度超出窗格时 stage 滚动，不挤压其它区域。

**机型预设**（逻辑像素，竖屏）：

| id | 名称 | 宽 × 高 |
|---|---|---|
| `iphone-se` | iPhone SE | 375 × 667 |
| `iphone-14-pro` | iPhone 14 Pro | 393 × 852 |
| `pixel-7` | Pixel 7 | 412 × 915 |
| `ipad-mini` | iPad mini | 768 × 1024 |
| `custom` | 自定义 | 用户输入，范围 240–1920 × 320–2400 |

横屏时宽高互换。

**UA**：进入模拟时 `view.setUserAgent(MOBILE_UA)`，退出时调用
`view.setUserAgent('')` 还原为空（Electron 会回落到默认 UA，
探针已确认恢复后 UA 不含 iPhone）。

**和缩放的冲突**：设备模拟与 `setZoomFactor` 同时生效会让视口失真。
进入模拟时把缩放重置为 100%，退出时恢复进入前的值。工具栏的缩放按钮
在模拟态下禁用并给出提示。

**已知局限**：`screen.width` 仍是宿主屏幕宽度（1920），因为 webview
没有 preload 桥可以提前覆写。少数依赖 `screen.width` 的库会判断错，
但常见的 `matchMedia` / `innerWidth` / UA 判断都正确。本版接受这个局限。

**持久化**：设备模式属于页签状态，存进 session。`src/types.ts:39` 的 `Tab`
新增 `device?: DeviceProfile | null`；`desktop/session.js` 的 `normalizeTab`
补同样的字段并做范围钳制（与现有 `splitRatioByGroup` 一致的做法）。

### 三、AI 页签状态与未读

**状态来源不变**。`src/App.tsx:270-301` 已经在 `subscribeAllData` 里
按 session 累积输出并调用 `classifyModelOutput`。本版只改三处。

#### 1. 空闲判定放宽

`src/App.tsx:293` 现在是 8000ms 无输出就判 idle。AI CLI 在长时间思考
（比如等一个慢命令）时可能十秒不出一个字节，会被误判为「已完成」，
反而制造假警报。改为有名常量 `IDLE_RESET_MS = 15000`。

#### 2. 未读标记

新增状态 `unreadBySession: Record<string, boolean>`，规则：

| 触发 | 结果 |
|---|---|
| 状态从 `running` / `waiting` 变为 `idle` 或 `error`，且该页签不是当前激活页签 | 置为未读 |
| 该页签被选中（`selectTab`） | 清除 |
| 未读之后又收到新输出 | 清除（它又跑起来了） |
| session 被销毁 | 清除 |

「不是当前激活页签」要按**左右分栏各自**判断：分栏模式下左右两侧可能
同时显示两个页签，两边都算「看过」。

#### 3. 展示

- **页签**：AI 类页签（`isCliTool(tab.shellId)`）在 `#编号` 前面插入
  `.tab-lamp`，复用 `.group-lamp` 的四色规则（`src/styles.css:322-345`）。
  未读时加 `.is-unread`，表现为灯外一圈脉冲。
- **侧栏**：`modelStatusByGroup` 旁边补一个 `unreadByGroup`，
  项目行有未读时在灯上显示同样的一圈。这样在别的项目里也能看到
  「B 项目有任务跑完了」。

`TabStrip` 需要新增两个 prop：`modelStatusBySession`、
`unreadBySession`。三个调用点（`src/App.tsx:2660`、`2709`、`2759`）同步补上。

## 数据流

```
pty 输出 ──subscribeAllData──> App: 累积输出 → classifyModelOutput
                                   │
                                   ├─ modelStatusBySession[sessionId]
                                   ├─ unreadBySession[sessionId]（过渡时置位）
                                   │
                                   ├─ modelStatusByGroup（rollup）
                                   └─ unreadByGroup（any）

TabStrip ← modelStatusBySession / unreadBySession
Sidebar  ← modelStatusByGroup / unreadByGroup
```

## 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| ~~`enableDeviceEmulation` 对 webview 不生效~~ | 已实测确认**不可用**，视口会被缩放成 981×1744 | 改用纯前端设置元素尺寸，探针已验证 375×667 正确 |
| `screen.width` 与设备不符 | webview 无 preload 桥，无法提前覆写 `screen` | 接受；媒体查询、innerWidth、UA 均正确 |
| `before-input-event` 与网页自带快捷键冲突 | 部分网页把 F5 绑成自己的行为 | 我们 `preventDefault` 后接管，行为可预期；用户要的正是统一刷新 |
| 未读标记误报 | 启发式判定本身不精确 | 15s 阈值 + 新输出即清除，宁可漏报不要误报 |
| 分栏左右同时显示 | 只按单一 activeTab 判断会误清未读 | 按左右两侧页签集合判断 |
| session 字段新增导致旧存档丢失 | `normalizeTab` 会丢掉未列出的字段 | 新增字段可选，缺省为 `null`，旧存档按桌面模式恢复 |
