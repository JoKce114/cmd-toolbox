# v1.3.0：编辑器外观设置与开机自启动

日期：2026-10-29
状态：待实施
前置：`2026-10-29-git-panel-history-stash-design.md`

## 背景

编辑器的字号、行高、字体目前**写死在 CSS 里**（`src/styles.css:850-858`），
用户无法调整。终端的字号早就可以通过设置或 Ctrl+滚轮调整，编辑器却没有对应入口，
长文件阅读和演示场景下很受限。

同时应用缺少开机自启动开关。这是一个独立于编辑器的应用级偏好，
本版一并补上，并借机把设置面板的页签结构补完整。

## 需求范围

### 做

- 编辑器设置新增：字号拖动条、行距拖动条、字体系列下拉
- 编辑器设置新增显示开关：显示行号、高亮当前行、括号匹配、显示空白字符
- 编辑器支持 Ctrl+滚轮缩放字号，与终端行为一致
- 设置面板新增「常规」页签，内含开机自动启动开关
- 编辑器页签内部按字体 / 显示 / 缩进三组排列

### 不做

- 自定义字体名输入（只列 Windows 自带三项）
- 编辑器字号与终端字号联动
- 启动后最小化到托盘（当前应用没有托盘图标，不做）
- 卸载时清理开机启动项（见「已知表现」）
- 括号自动闭合、自动保存、行尾空白处理等行为类设置（留给后续版本）

## 数据模型

### `src/prefs.ts`

`fontSize` 语义是「终端字号」，新增编辑器字段后会长期误导，本版改名为
`terminalFontSize` 并做一次性读取兼容。

```ts
export type EditorFontFamily = 'consolas' | 'courier' | 'lucida';

export type AppPrefs = {
  terminalFontSize: number;
  copyOnSelect: boolean;
  editorFontSize: number;
  editorLineHeight: number;
  editorFontFamily: EditorFontFamily;
  editorWordWrap: boolean;
  editorLineNumbers: boolean;
  editorHighlightActiveLine: boolean;
  editorBracketMatching: boolean;
  editorShowWhitespace: boolean;
  editorTabSize: number;
  editorIndentWithSpaces: boolean;
  editorKeybindings: KeyBindingMap;
};
```

| 字段 | 范围 | 步长 | 默认 |
|---|---|---|---|
| `terminalFontSize` | 11–20 | 1 | 13 |
| `editorFontSize` | 11–32 | 1 | 13 |
| `editorLineHeight` | 1.0–3.0 | 0.05 | 1.5 |
| `editorFontFamily` | 三选一 | — | `consolas` |
| `editorLineNumbers` | 布尔 | — | true |
| `editorHighlightActiveLine` | 布尔 | — | true |
| `editorBracketMatching` | 布尔 | — | true |
| `editorShowWhitespace` | 布尔 | — | false |

**迁移**：`readPrefs` 里按 `parsed.terminalFontSize ?? parsed.fontSize` 取值，
旧用户升级后终端字号不变。

**浮点处理**：`editorLineHeight` 步长 0.05，滑块会给出 `1.2000000000000002`
这类值，读取时必须 `Math.round(value * 100) / 100`，否则会存进长尾浮点数
并在设置里显示成 `1.2000000000000002×`。

字号和行距都做 clamp，非法值或越界值回落到默认，与现有 `editorTabSize` 的处理一致。

### `src/types.ts`

```ts
export type LoginItemState = {
  supported: boolean;
  enabled: boolean;
  reason?: string;
};

export type LoginItemResult = { ok: true } | { ok: false; message: string };
```

## 编辑器外观

### 字体栈

只列 Windows 自带、且实际能用的三项，每项都带中文兜底：

| 下拉文案 | font-family |
|---|---|
| Consolas（默认） | `Consolas, "Microsoft YaHei", monospace` |
| Courier New | `"Courier New", "Microsoft YaHei", monospace` |
| Lucida Console | `"Lucida Console", "Microsoft YaHei", monospace` |

链尾必须保留中文字体：Consolas 没有中文字形，中文注释靠后面的微软雅黑兜底；
去掉会导致中文掉进别的字体，行高看起来会跳。

不列 Cascadia Code / JetBrains Mono：本机实测未安装，列了也不会报错，
只会静默回落，看起来像设置没生效。

### 外观扩展（`src/editorTheme.ts`）

```ts
export function editorAppearanceExtension(opts: {
  fontSize: number;
  lineHeight: number;
  fontFamily: EditorFontFamily;
}): Extension
```

设置三项：`&` 的 `font-size`、`.cm-scroller` 的 `font-family` 与 `line-height`。
行号槽（`.cm-gutters`）通过继承自动跟随字号，不需要单独写尺寸。

**必须同步删除 `src/styles.css:850-858` 里的三条声明**
（`.cm-editor` 的 `font-size: 12.5px`、`.cm-scroller` 的 `font-family` 与
`line-height: 1.5`），只保留 `.cm-editor { height: 100% }`。

原因：静态 CSS 的优先级会覆盖 CodeMirror 主题生成的类，留着的话设置改了不生效，
而且不会有任何报错——这是本版最容易踩的坑。

### 显示扩展

四个开关分别控制 `lineNumbers()`、`highlightActiveLine()`、
`bracketMatching()`（来自 `@codemirror/language`）、`highlightWhitespace()`
（来自 `@codemirror/view`）。

注意 `lineNumbers()` 和 `highlightActiveLine()` 现在写死在
`CodeMirrorHost.tsx:165-166` 的静态扩展列表里，必须移进 Compartment 初值，
否则开关无效。

### `CodeMirrorHost` 新增两个 Compartment

沿用现有 wrap / indent / keys 的模式，只重配不重建编辑器：

| Compartment | 内容 | 依赖 |
|---|---|---|
| `appearanceRef` | 字号、行距、字体 | `fontSize`、`lineHeight`、`fontFamily` |
| `displayRef` | 行号、高亮当前行、括号匹配、空白字符 | 四个开关 |

### Ctrl+滚轮缩放

在 host 容器挂 `wheel` 监听，照抄终端已有的写法
（`TerminalPane.tsx:289-296`）：`{ capture: true, passive: false }`，
`ctrlKey || metaKey` 时 `preventDefault()` 并回调 `onFontSizeDelta(±1)`。

回调路径 `CodeMirrorHost → EditorPane → App.tsx`，在 `App.tsx` 里 clamp 到
11–32 后写 prefs，与终端的 `onFontSizeDelta` 完全对称。

`passive: false` 是必需的：默认 passive 监听里 `preventDefault()` 无效，
Chromium 会同时执行页面缩放，表现为字号和整页一起变大。

## 设置面板

### 页签顺序

`关于 / 常规 / 终端 / 编辑器 / 快捷键`

「关于」必须第一位（`tests/update-notify.mjs` 有断言）。「常规」紧跟其后。

### 编辑器页签分三组

当前 3 项变成 10 项，一屏全是卡片，必须分组。新增 `.settings-group-title`
小标题样式（现有 `.settings-group-head` 只有备注和「恢复默认」链接，没有标题位）。

| 分组 | 项 |
|---|---|
| 字体 | 字号（滑块）、行距（滑块）、字体系列（下拉） |
| 显示 | 自动换行、显示行号、高亮当前行、括号匹配、显示空白字符 |
| 缩进 | 缩进方式、缩进宽度 |

行距显示成 `1.50 · 19.5px`，后面是折算出的像素行高，拖动时能直观看到变化。

滑块、下拉、开关全部复用现有 `.settings-slider` / `.settings-select` /
`.settings-switch`，不新造控件。

### 常规页签

一项：开机自动启动开关。不可用时置灰并显示原因。

### 保存语义：开机启动在「保存」时生效

设置面板现有心智模型是「改了 → 点保存 → 取消则全部丢弃」。
开机启动虽然写的是系统状态，也必须守同一套规则，否则用户点了取消
却发现注册表已经被改，属于最糟糕的那种意外。

```tsx
const handleSave = async () => {
  if (launchOnStartup !== loginItem.enabled) {
    const result = await onSetLoginItem(launchOnStartup);
    if (!result.ok) {
      setLoginError(result.message); // 面板保持打开
      return;
    }
  }
  onSave({ ... });
};
```

保存过程中按钮进入 busy 状态，防重复点击。每次打开面板都重读注册表真实状态，
所以显示永远与实际一致。

组件新增 props：

```ts
loginItem?: LoginItemState;
onSetLoginItem?: (enabled: boolean) => Promise<LoginItemResult>;
```

## 开机自启动

### 新增 `desktop/login-item.js`

工厂函数注入 `app`，便于离线测试：

```js
createLoginItem(app) → { getState(), setEnabled(enabled), repairOnStartup() }
```

**可执行文件路径**：

```js
const exePath = process.env.PORTABLE_EXECUTABLE_FILE || process.execPath;
```

便携版运行时会先解包到临时目录，`process.execPath` 指向**临时目录里的 exe**，
写进注册表后下次开机启动会因临时目录已清空而失效。
`PORTABLE_EXECUTABLE_FILE` 是 electron-builder 为便携版注入的真实路径。
安装版没有这个变量，回落到 `process.execPath`，行为不变。

`getState()`：`app.isPackaged` 为 false 时返回
`{ supported: false, enabled: false, reason: '开发模式下不支持开机启动' }`；
否则用 `app.getLoginItemSettings({ path: exePath, args: [] })` 读注册表真实状态。

`setEnabled(bool)`：写入后**再读一次校验**，不一致则返回失败并提示
「系统拒绝写入开机启动项，可能被安全软件拦截」。本机装有 360，
静默拦截 Run 键是现实存在的，不校验会显示成功但实际没生效。

`repairOnStartup()`：应用启动时若已开启，用当前路径重写一遍。
便携版被挪目录、或从旧路径升级后，开机项会自动指向新位置。

注册表值名固定 `Cmd Toolbox`，会显示在任务管理器「启动」列表里。

### IPC 四点齐改

| 位置 | 内容 |
|---|---|
| `desktop/main.js` | `ipcMain.handle('app:get-login-item')` / `('app:set-login-item')`，`whenReady` 里调 `repairOnStartup()` |
| `desktop/preload.js` | `loginItem: { get: () => invoke('app:get-login-item'), set: (enabled) => invoke('app:set-login-item', enabled) }` |
| `src/global.d.ts` | `loginItem` 的类型声明 |
| `src/App.tsx` | 打开设置时读取状态、传给 `SettingsModal` |

## 测试

### 新增 `tests/login-item.mjs`（离线，不需要 GUI）

用假的 `app` 对象（`isPackaged`、`getLoginItemSettings`、`setLoginItemSettings`）
验证：

- 开发模式返回 `supported: false`，`setEnabled` 不调用写入
- 写入后读回不一致 → 返回失败（模拟安全软件拦截）
- `repairOnStartup` 在已开启时用当前路径重写，未开启时不写
- `PORTABLE_EXECUTABLE_FILE` 存在时优先使用它

**绝不触碰真实注册表。**

### 扩写 `tests/settings.mjs`

- 「常规」页签存在，开机启动开关在开发模式下置灰并显示原因
- 拖字号滑块 → `.cm-editor` 的计算字号变化
- 拖行距滑块 → `.cm-scroller` 的计算行高变化
- 关行号 → `.cm-gutters` 消失；再开启 → 恢复
- 开空白字符 → `.cm-highlightSpace` 出现
- 括号匹配 → 光标移到括号内侧后出现 `.cm-matchingBracket`

现有断言 `['关于', '终端', '编辑器', '快捷键'].every(...)` 是包含式判断，
新增页签不会让它失败；「默认停在关于页签」的断言保持不变。

## 已知表现（不是缺陷）

- **行距调到 1.0 附近时，选区高亮和光标会与上下行视觉重叠**。
  这是有意开放的范围，不修。
- **卸载时不会清理开机启动项**。若卸载前开关是开的，会留下一条指向
  已删除 exe 的死条目。彻底解决需要 `nsis.include` 自定义卸载脚本，留给后续版本。
- **开发模式与所有自动化测试环境下开机启动不可用**（`app.isPackaged` 为 false），
  开关置灰。因此该功能无法在 Playwright 里端到端验证，只做离线单元测试。
